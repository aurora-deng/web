# NEBULA 可观测性实战

## 第一部分 · 我自己做实验

1. **会看三个健康状态。** 启动隔离实例，记录存活、业务就绪和指标抓取。将缺数据与数值为零各截图一次。用 `/metrics` 的 401/403/200 解释为何单独管理采集凭据。
2. **会看慢请求。** 先导入 4 个与 16 个工作端的压测。在业务性能页对齐时间，找到队列、连接池、COMMIT 和 ACK 就绪的变化。将最慢一条客户端 RTT 对到 ACK 采样，写出仍待验证的阶段。解释为什么两个 P99 相减无法得到另一个 P99。
3. **会用 trace。** 运行独立探针，打开同一个 trace ID，指出 probe、HTTP handler、SQL 客户端调用的父子关系。解释客户端往返与 handler 开始计时的边界。
4. **会做故障演练。** 在实验前写下 live、ready、采集、重试的预计变化。运行隔离的数据库和进程测试，核对恢复时间、消息 ID 与数据库行数。
5. **会接一类新来源。** 从 DAG、Agent 或设备样例任选一个，核对契约字段、手工重复一次上报，解释为什么明细 ID 不应该成为指标标签。

按[启动与验收指南](setup.md)执行。每次抄录：版本、测试命令、样本量、错误、UTC 时间窗、观察、推测、下一项能推翻推测的实验。最终交两张图和一份可复现记录，可用作面试演示。

## 第二部分 · 给助教的提示词

```text
带我学习 NEBULA 研发诊断平台第 [课号] 课。我懂 Webserver 基础，当前对遥测是新手。
先核对我手里的分支和已有实验，再讲一个概念，用真实代码和样例输出让我动手。
帮助我沿告警时间窗查看指标、span 与事件，把观测、推测和待验证的假设写清。
同条消息对齐比较。记录样本量、错误和测量环境。小型统计用 Python，线程所有权用 C++。
先让我预测故障后各状态，再使用本轮脚本拥有的临时进程和数据库演练。
每一步用一道自检题，等我复述和决定后再继续。
```
