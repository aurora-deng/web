# 我对各层测试的理解（学员笔记汇总）

> 把学习过程中形成的「一句话理解」集中放在这里，方便复习。  
> 各章正文里也有同名小节，细节以分章为准。

---

## 总分层

| 层 | 我的理解（一句话） |
|----|-------------------|
| **单元测试** | 预先定义「程序应该产生什么行为」，再自动验证实际行为是否符合预期。 |
| **断点调试** | 人钻进过程里找「为什么不符合预期」。 |
| **黑盒测试** | 站在客户端角度，用真协议访问服务器，不关心内部实现，看行为对不对。 |
| **Benchmark** | 大量请求下还能不能又快又稳（QPS / 延迟 / 错误率）。 |
| **Sanitizer** | 给程序加运行时监控，抓越界、UAF、数据竞争等隐藏缺陷。 |
| **故障注入** | 主动制造坏环境/坏客户端节奏，看系统稳不稳。 |
| **Fuzz** | 自动砸大量怪输入，主要看会不会崩（输入健壮性）。 |
| **Metrics** | 在业务路径上埋点记账，再通过出口读出状态——不是旁路偷窥线程。 |
| **火焰图** | 看 CPU 时间堆在哪个函数调用栈上（横向越宽越热）。 |

总口诀：

> **单元测零件，黑盒测机器，Benchmark 测性能；Sanitizer/Fuzz 管安全健壮；Metrics/火焰图管观测定位。**
