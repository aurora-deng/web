# 10 · 工程化流水线与验收（详细讲义）

> 前面九章是「会用每一种武器」。  
> 这一章把它们收成：**改代码 → 自动验证 → 出报告** 的工程习惯，并给你验收清单与简历表述。

---

## 我对工程化验收的理解（笔记）

**核心定义（自己的话）：**

> **工程化 = 不要靠人脑记「今天测了没」，而是把「编译 → 单元 → 黑盒 →（可选）Sanitizer/Fuzz/压测」收成可重复流程；每次改代码都走同一套门禁。**

闭环用自己的话串起来：

```text
零件对不对     → GoogleTest
整机行为对不对 → 黑盒
快不快         → Benchmark
安不安全       → Sanitizer / Fuzz
肚子里怎样     → Metrics
CPU 在哪       → 火焰图
坏环境稳不稳   → 故障注入
```

验收不是「名词凑齐」，而是：**该绿的绿、该有基线数字的有数字、改架构知道回归哪几条。**

---

## 1. 为什么还要「流水线」？

如果每次都靠人记：

```text
今天跑单测了吗？ASan 呢？压测基线对比了吗？
```

一定漏。工业做法是 **CI（持续集成）思想**：

```text
提交 / 合并
  → 自动编译
  → GoogleTest
  → 黑盒
  → （可选）ASan / Fuzz
  → （可选）Benchmark 对比
  → 生成报告（绿/红）
```

工具可以是 GitHub Actions / GitLab CI / Jenkins；  
本仓接近的一键入口：`bash scripts/gen_report.sh`。

流水线是壳，**内核仍是 00～09 的分层闭环**。

---

## 2. 完整闭环（请背熟）

```text
修改代码
   │
GoogleTest          零件对不对
   │
黑盒测试            用户行为对不对
   │
Benchmark           性能数据（对比基线）
   │
Metrics（若有）     肚子里哪里堵
   │
Fault Injection（若做） 坏环境稳不稳
   │
ASan / TSan / Fuzz  隐藏缺陷
   │
修复
   │
再 Benchmark；必要时火焰图定位 CPU
```

一句话复习：

> **单元测零件，黑盒测机器，Benchmark 测性能，Sanitizer/Fuzz 测安全健壮，Metrics/火焰图测观测与定位。**

---

## 3. 改哪一类代码，至少回归什么？

| 你改了什么 | 至少跑什么 |
|------------|------------|
| Parser / Buffer | 单元 Parser/Buffer +（可选）Fuzz |
| Session / Keep-Alive | 黑盒 Keep-Alive / 流水线 |
| Executor / 唤醒 | `/slow`+`/fast`；（深挖）TSan |
| 背压 / 连接上限 | 黑盒限制 + 压测错误率 |
| 发送 / sendfile / Range | 相关黑盒 |

不变量练习材料：[../ROUND1_INVARIANTS.md](../ROUND1_INVARIANTS.md)。

## 4. 第三阶段项目「测试体系」验收清单

### 正确性

- [ ] Buffer / Parser / Router 核心单元测试绿  
- [ ] 黑盒：GET、404、Keep-Alive、半包或流水线、异常输入  
- [ ] 慢请求不堵同 Reactor 上的快请求  

### 安全与健壮

- [ ] ASan 下黑盒（及中等压力）干净  
- [ ] TSan 下并发场景无 data race（单独构建）  
- [ ] Fuzz：Parser 无新增崩溃  

### 性能与观测

- [ ] 有一份 Release 基线（QPS + P99 + Error≈0）  
- [ ] 重大优化有前后对比  
- [ ] （进阶）Metrics 能解释一次性能下跌  
- [ ] （进阶）异常时能采火焰图说明热点  

### 故障（进阶；本仓未强制落地）

- [ ] 慢客户端会超时释放  
- [ ] 延迟/断开场景无泄漏、无 UAF  

对照「讲义完整体 vs 本仓已有」：[../CLOSED_LOOP_MAP.md](../CLOSED_LOOP_MAP.md)。

## 5. 简历表述模板（可按实际裁剪）

> 基于 C++ 实现高性能 HTTP 服务器，采用 Reactor 多线程与非阻塞 IO（协程 Session / Executor）；构建稳定性验证体系：GoogleTest 单元测试、Python TCP 黑盒、ASan/TSan、wrk 压测基线、HTTP Parser libFuzzer；掌握 Benchmark→观测→定位的性能工程方法（Metrics / perf 火焰图按阶段选用）。

有基线数字时，把「约 xxk QPS / P99」写进项目描述会更硬。
