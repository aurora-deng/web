## A. 自测题标准答案

### 1. 单元和黑盒本质差别？各举本仓一例。

**标准答：**

- **单元**：在进程内、隔离地检查**组件契约**（输入→状态/输出是否符合约定），不启动完整服务器、不依赖真 TCP。  
  - 例：`HttpParserTest.WaitsForHalfPacketAndContentLengthBody`（半包拼齐）。  
- **黑盒**：启动**真实可执行文件**，只通过 **TCP/HTTP 字节**观察行为；测的是整机链路，不 include 内部头文件。  
  - 例：`GET /slow` 进行中 `GET /fast` 必须立刻成功（Executor 边界）。

**易错：**「单元=功能能不能用，黑盒=只测突发」——黑盒也含正常路径（`GET /`）；单元也含拒绝/超限等边界。

---

### 2. 「半包」和「流水线」各哪条用例？不变量？

**标准答：**

| 概念 | 主要用例（单元） | 不变量 |
|------|------------------|--------|
| 半包 | `WaitsForHalfPacketAndContentLengthBody` | 数据不够 → NEED_MORE，状态保留；凑齐后一次交付完整请求 |
| 流水线/粘包 | `LeavesPipelinedRequestInBuffer` | 只消费当前请求字节；下一请求完整留在 Buffer |

**补充：**黑盒里的 pipeline 是**端到端**「一次写入多请求、按序应答不串包」，与单元「Buffer 里还剩第二份请求」互补，不是互相替代。

**易错：**「半包用单元、流水线只用黑盒」。

---

### 3. 为什么 404 测试要看 `context.response`？

**标准答：**

`Router` 未匹配时 `make404` 会从 **response 池**取出新对象，并改写 **`ctx.response` 指针**；测试栈上原先那份 `HttpResponse` 可能仍是默认 200/空 body。  
因此断言必须对准**真正生效、即将作为响应的那份**：`context.response->status` / body，而不是栈上旧对象。

**易错：**「因为 404 是响应给出的」——太笼统，没点到「池对象替换指针」。

---

### 4. `/slow`+`/fast` 红了更可能坏哪层？Parser 全绿能排除什么？

**标准答：**

- 更可能坏在：**Executor 提交/完成通知**、**Session 在 ExecuteAwaiter 上的挂起与唤醒**、或 handler 又跑回了 Reactor 线程。  
- Parser 全绿：大致说明 **HTTP 解析组件契约**仍在。  
- **排除不了**：线程边界、完成队列、僵尸唤醒、停服竞态等。

**易错：**「全绿表示请求解析全部正常所以边界也没问题」——解析≠调度边界。

---

### 5. 「池满→503」有没有黑盒？缺口还是必补？四层与回归？

**标准答：**

- 当前**没有**专门把 ThreadPool 队列打满并断言 503 的黑盒 → **已知缺口**。  
- 收尾第一轮**不必立刻写码**；知道「不变量存在、证据还缺」即可。  
- **四层** = 单元 / 黑盒 / 压测 / fuzz（证明点不同）。  
- **回归** = 改完相关代码后，再跑**应该能抓住回归的那批用例**（改 Executor 则优先黑盒 `/slow`/`/fast` + 相关单元），不是「触顶信号」。

## B. 「不变量」口诀（过关后应能背）

Parser：半包要等、粘包要剩、冲突要拒、超限要死、交付要 reset。  
Executor：Worker 可堵自己，不得堵同 Reactor 上其他连接。  
断言：对准真正生效的对象（尤其池化/换指针）。
