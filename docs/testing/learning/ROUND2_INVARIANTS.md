# 测试学习 · 第二轮：口述「想有的」不变量

> 前置：第一轮已过关（[ROUND1_ANSWERS.md](ROUND1_ANSWERS.md)）。  
> **本轮目标**：练习「先写不变量，再谈要不要写测试」；**本轮仍不写代码**。  
> 你交卷方式：直接在对话里列出 3 条（见下方格式）。

---

## 1. 题目

请提出 **3 条** 你认为「系统应该永远满足」、但**当前仓库可能还没有直接证据**（没有对应用例，或只有间接覆盖）的不变量。

每条用这个格式：

```text
不变量：……（一句话，永远为真）
为何重要：……（一句话）
现有证据：无 / 仅间接（说明哪条测试沾边）
若要测：单元 or 黑盒 or 压测？（先选层，不写码）
```

---

## 2. 怎样算一条「好」不变量

**好：**

- 可证伪：能想象出一个会红的实验。  
- 贴本仓：Runtime / Executor / 解析 / 停服 / 背压之一。  
- 不依赖「感觉更快」：避免「QPS 必须 > 5 万」这种设备绑定指标当不变量。

**不好：**

- 「系统要稳定」「代码要优雅」。  
- 「要支持 HTTP/2」（那是功能扩张，不是收尾期不变量）。  
- 与已有用例完全重复（如再写一遍「半包要 NEED_MORE」）。

### 启发方向（任选，勿照抄当交卷）

已知缺口/薄弱处可作灵感：

- 执行队列满 → **503**（单元/黑盒几乎没打满池）  
- 停服后 **listen 尽快释放**、旧连接如何收尾  
- 连接数触顶后的行为  
- Worker 异常 → 客户端看到 **500** 且 Reactor 不崩  
- 读水位背压恢复后仍能继续读  

也可从 CLOSED_LOOP_MAP 想：故障下错误率、Sanitizer 下无报 —— 但请写成**可测的一句话**，不要写「要做混沌平台」。

---

## 3. 批改时我会看什么

1. 是否真是不变量（可红）。  
2. 「现有证据」判断是否靠谱。  
3. 选的测试层是否合适（别用单元测真多线程调度边界，除非 mock 得很干净；别用压测证明协议对错）。  

---

## 4. 交卷口令

在对话中发送例如：

```text
第二轮交卷
1. 不变量：…
   为何重要：…
   现有证据：…
   若要测：…
2. …
3. …
```

批改通过后，可再选：`开始写测试练习`（从你的 3 条里挑 1 条落最小用例）或 `结束测试学习`。
