# Phase46：前端单一上下文与真实业务交互

## 1. 聊天入口职责

原 `app.js`的95个函数提取到9个控制器；入口仅启动 `ChatApplication`。它创建一份 `ChatContext`，装配动作接口并注册 `ChatBindings`。没有复制第二份用户、会话或待发队列。

| 控制器 | 职责 |
|---|---|
| FeedbackController | 统一请求、错误、提示及基础展示函数 |
| ConversationController | 登录/退出、会话摘要/打开、能力读取、公告生命周期 |
| MessageController | 消息视图、分组、回执/撤回、搜索和上下文定位 |
| RealtimeController | WS/SSE、重连预算、待发核对、ACK和恢复 |
| ContactsController | 好友/申请/黑名单、备注和联系人默认偏好 |
| GroupController | 成员、角色、禁言、移除和群资料 |
| AttachmentController | 分片上传、附件状态与大小提示 |
| AiController | 模型目标、AI回包、引用和训练授权交互 |
| KnowledgeController | 私有/群资料目录与授权操作 |

每个控制器通过工厂取得共享上下文，返回明确动作；没有模块导入时隐式重复注册事件。静态DOM监听集中在一个AbortController中；页面销毁停止监听、定时器、连接、播放器和虚拟列表。切号取消该账号的请求，迟到结果不再进入新账号状态。`BusinessApi`统一401/403/409/429、AbortError、网络错误和结果不确定的写入；普通写请求不会自动重放。聊天固定幂等键重试继续由ReliableSender负责。

## 2. 未读和偏好为什么必须有刻度

未读不是本地增量与服务器数字取较大值。`UnreadWatermarks`合并已接受最高消息序号和已确认已读序号，二者只向前走：`unread=max(highest-read,0)`。旧快照20/10期间收到21、22，会显示12；另一端读到22后归零，旧快照不再把红点复活。重复和乱序消息不多加。新摘要水位用十进制字符串；组件内部BigInt，旧DTO仍兼容。

`PreferenceSnapshots`按偏好revision合并PATCH结果、HTTP列表和WS事件。旧版本不能覆盖新设置；同一版本不会用不同载荷反转状态。账号退出时两个账本清空。

## 3. 实际交互

- 用户选择器按用户名/显示名查公开目录，结果回填原有好友/私聊/群成员DTO；支持多选，保留高级ID输入兼容，服务端仍独立检查权限。
- 会话详情新增免打扰，成功以服务端响应为准。群和私聊均支持，提示明确“消息与未读仍同步”。
- 搜索选择当前/全部会话、游标翻页，点结果直接请求有界上下文。`ChatHistory.focusContext`只切换可见窗口，不把跳过的历史伪装成连续恢复水位；随后仍可向前/后翻页。
- 同人、同日、五分钟内、没有系统/撤回隔断才分组；判断来自消息数据。一条消息仍对应一个虚拟项，日期分隔留在该项内；虚拟窗口首行重新显示头像/作者，避免截断后不知是谁。
- 上传选择器和提示读取服务端能力；树媒体上传器按用途校验，并复用分片协议。客户端检查只是反馈，实际类型/签名/时长/权限仍由后端判断。

## 4. 视觉与资源边界

保留设计Token、深浅主题、原聊天底部输入和真实空态。神树保持花冠、恶魔果实风格、LOD、实例化、后台停帧和列表降级；桌面将文案和3D视口分开，移动端折叠装饰文案。没有添加像素亮度读回和后处理。

本轮新浏览器场景使用431条、跨三天、含长文本/附件的历史，检查160项以内的可见DOM、六组尺寸/主题截图、用户选择器、免打扰、全局搜索游标、上下文与较新分页。原可靠性回归继续检查ACK丢失、固定ID重试、断线补发、管理员撤回。浏览器API替身不替代真实HTTP/PG测试，也不证明真实云模型可用。
