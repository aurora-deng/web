# 第三阶段重要知识点 · 06 BackPressure（背压）

> **标记**：第三阶段重要知识点  
> **对应代码**：`pauseByMemory` / `MAX_PENDING_BYTES`、`MAX_THREAD_POOL_QUEUE`→503、`maxConnections_`

---

## 1. 核心命题

服务器不是「来多少收多少」，而是：

> **入口速度 > 处理速度时，必须限制入口或明确拒绝，否则内存/队列/fd 爆炸。**

---

## 2. 分层水位（思想）

```text
accept 连接数
  → readBuffer / 入站字节
    → 待执行任务队列（Executor）
      → 待发送响应积压（写侧）
```

每层都应有界。

---

## 3. 本仓已有闸门

| 层 | 机制 | 过载表现 |
|----|------|----------|
| Accept | `maxConnections_`（默认 10000） | 超额关闭新连接 |
| 读 | `pauseByMemory` + 撤销 EPOLLIN | 暂停读，水位下去再恢复 |
| 执行 | 线程池队列上限，`submit` 失败 | **503**，且常关 keep-alive |

写积压 / pipeline 队列水位：思想重要；代码上以读水位 + 执行队列为主，可按需补强。

---

## 4. `updateEvent` / 停 EPOLLIN 的含义

超过高水位 → 不再关注可读 → 内核接收窗口最终反压到对端 → **用协议与 IO 事件做限流**，不是无限 `recv` 进用户态。

---

## 5. 验收思路（见 09）

人工把 Worker 数调极低 + 打高并发 → 应看到拒绝（503）或读暂停/恢复，而不是 OOM 或全连接假死无响应。
