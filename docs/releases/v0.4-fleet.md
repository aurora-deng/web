# v0.4-fleet 发布说明

本版基于 `Function3.6` 分支的 `a084b09`，在 M09 暂停并回到 Fleet Agent、DAG 与交付工程。Tag 对应实际进入 ZIP 与 Docker 镜像的源码 `fb4bd56c08c36c5fd8309c1014e00b47e732dc83`。发布分支增加了这份说明与测试证据。 [与 Function3.6 的代码差异](https://github.com/aurora-deng/web/compare/Function3.6...v0.4-fleet)

## 主要变化

| 范围 | 本版交付 |
|---|---|
| Fleet Agent | C++ 通过现有 Ollama 客户端生成提案。技能目录和证据策略共同校验候选。三项只读工具取工单证据，写操作经人工审批。SQLite 保存检查点和有界工单记忆。 |
| DAG | Fleet 审批回执丢失后可向协调器对账。独立 PostgreSQL 队列用固定租约和尝试代次控制双 Worker 接管。C++、浏览器和 Observer 统一观测状态。Observer 甘特图高亮实际尝试构成的依赖关键路径。 |
| 消息库 | 027 迁移按 `processed_at` 为 Inbox 补索引，分批清理超过 14 天且已投递的记录。在同一事务保留迟到重投的去重依据。 |
| 交付 | 从干净检出编译 Web 与 Fleet，验 Linux ZIP、启动 Docker 容器、导出及重载镜像。保存主要工具和依赖制品的版本与 SHA-256。 |

**真实模型**。用本机已有的 `qwen3:8b-q4_K_M` 和合成工单测试。冷启动三次均在约 12.1 秒回退到规则。另一次先单独加载模型，耗时 16.0 秒，之后一轮回退、一轮在 7.57 秒返回通过校验的提案，进入人工待审。非法 `skillId` 和越权候选的拒绝由可复验的 HTTP 合约覆盖。 [冷启动](../../artifacts/v0.4-fleet/ollama-cold.json) · [预加载后](../../artifacts/v0.4-fleet/ollama-warm.json)

**运行边界**。Docker 离线档需要兼容的 Linux x86-64 主机库，应用与车队各自使用隔离数据库或账本。双 Worker 接管在同一台 CentOS 的两个进程验证，当前租约时长固定。Fleet 后端记忆保存受授权的工单上下文，网页版小研使用原个人会话。M09 时序与双仿真体压力门禁保留原结论。 [复现与排查](../ops/validation/v04-fleet-reproduction.md) · [Agent/DAG 实操](../learning/v04-fleet-agent-dag.md) · [M09 原记录](../ops/validation/m09-actuator-control.md)
