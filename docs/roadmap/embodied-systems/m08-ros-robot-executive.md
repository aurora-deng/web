# M8 ROS 2 与本体大脑 · 子 Agent 的任务执行

P1 · S3。以你会用 ROS 小机器人为起点，把精力放在集成、诊断和故障生命周期。先做一台可以测的机器人。

实现接在独立 Fleet 边缘的 `robotics/nav2_gateway/`，复用原 gRPC 工单、身份、`epoch` 及恢复合同。仿真层从用户现有 ROS 工作区外单独启动。 [复验与使用](../../ops/validation/m08-ros-cross-vm.md) · [学习与排查](../../learning/m08-ros-lifecycle.md)

## 技术要求

- 用 `rclcpp` 实现边缘桥与本体执行器适配，维护任务状态、能力、准备度与安全状态。用 ROS 2 Action 承载可等待、可取消、带反馈的任务。
- 规划 TF、namespace、时钟和生命周期。导航及状态回调与 gRPC 长等待分别调度，限制跨层共享的队列和对象。
- 按消息用途规划 QoS。传感器重及时，任务状态重可靠与可恢复，保留资源上限和过期策略。实测 offered/requested 是否兼容。
- 本体执行前再次判断授权、范围、局部地图、状态新鲜度及冲突。失联、取消和本地停止分别有状态。

## 实施步骤

1. 基于目前可运行的 ROS 环境建一个独立工作区。先用仿真节点完成固定目标，记录 ROS、RMW、仿真器版本与资源预算。
2. 建立本体适配器。通信线程接收工单，执行器发出单次 ROS Action 和反馈，控制门检查任务许可。状态和 gRPC 跨线程队列有容量。
3. 定义 lifecycle 配置、激活、停用和清理分工。把「待命/执行/降级/安全态」写为独立任务状态，记录转移原因。
4. 为感知、任务状态和诊断选择 QoS。用实测说明配置取舍，增加状态超时和 callback group 排查夹具。
5. 用相同 protobuf 接入 M5，替代一个模拟边缘。加第二机器人前先跑 namespace、TF、取消和失联检查。

## 预期产出

一套 `rclcpp` 工作区设计、一台仿真机器人接入、技能适配与 QoS 速查表。进阶把本体节点接到已选硬件的官方驱动，逐级走 M12/M13。

## 验收标准

| 场景 | 通过条件 |
|---|---|
| 单机任务 | 5 次固定目标跑通接收、动作反馈、结果和 Observer 查询，任务 ID 可追到 Action |
| 重复激活与取消 | 至少 10 次生命周期循环，取消可确认，清理后活跃任务和待处理句柄回归基线 |
| 诊断 | 用一次 QoS 不兼容场景和一次长回调拥塞场景复验定位步骤；修改后同样输入通过 |
| 多机器人 | 两个实例可独立寻址和追踪，TF 设计与地图归属一致 |
| 断线 | 按本地允许策略保持或暂停；恢复对账后同旧命令的副作用最多一次 |

自测。收到导航 Action 的取消回复时，哪些状态能证明「任务已取消」，哪些证据证明「本体已经安全」。
