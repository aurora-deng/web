# M6 通信骨架 · gRPC、背压与断线恢复

P0 · S1–S2。控制流只承载有限的任务、回执和对账。低频设备状态可以汇总，高频传感器原始数据由本地录制与专用数据面处理。

## 技术要求

| 通道 | 行为 |
|---|---|
| 控制 | 有界双向流，握手认证、命令 ID、阶段回报、心跳和恢复游标 |
| 状态 | 独立预算，合并可覆盖的状态快照，慢消费者有可见丢弃和重建状态 |
| 证据与数据 | 低频摘要兼容 Observer，原始录包通过索引定位，带版本、权限和预算 |

单连接内按协议写入，业务身份从认证结果绑定。协议消息限制单条大小与队列的条数、字节，分开处理 RPC 报错、连接失活、任务 deadline 和租约。必要时用同一协议的独立连接隔离流控。

## 实施步骤

1. 定义 v1 协议的握手、能力、命令、回执、失联和对账字段。决定哪些 ID 在重连间保持不变，哪些每次连接更新。整理字段、状态和错误码表。
2. 用独立 coordinator 与 edge fixture 跑通两个方向。初始只回报确定性结果，先验证关闭、队列满与读写生命周期。C++ 业务/领域使用端口，gRPC 类型集中在适配器。
3. 给控制队列配置容量和准入。状态允许合并，控制满时返回明确过载或挂起派发计划。为不同队列记录深度、字节、丢弃和完整回执比例。
4. 增加心跳与退避重连。建立连接时核对身份、协议版本、运行代号、最近回执及活动命令。每次恢复依据 M5 状态机补发或对账。重复消息保持相同命令 ID。
5. 在隔离进程上演练慢消费者、连接中断、版本缺字段和重连，先自动化记录，再在受控的两主机网络环境验收。

## 预期产出

一个可读 proto 合同、C++ 服务和客户端样例、两类有界流、兼容与断连证据，以及延迟与资源简表。进阶交付把部署拓扑、实测跨机条件和身份签发/撤销策略纳入版本报告。

## 验收标准

| 场景 | 断言 |
|---|---|
| 基本流程 | 两个独立进程之间完整看到握手、命令、已接受、完成；兼容用例可拒绝不支持版本 |
| 背压 | 30 秒缓慢读取期间无无界增长；控制和状态水位有上限，合并/拒绝计数与注入一致 |
| 断连 | 20 次固定夹具在发送与回执之间断连；恢复后状态能由 M5 对账，逻辑动作副作用最多一次 |
| 延迟 | 每轮至少 1,000 次成功的应用 ACK，三轮记 P50/P95/P99 与丢弃，ACK 往返用发起机单调钟；跨机单程另附时钟误差证据 |
| 退出 | 正常关闭与截止时间触发时，已建立流归零，迟到回调无法写入放弃的会话 |

首轮以一台 Linux 上的两路模拟边缘、合计 10 条命令每秒、单条命令载荷最多 1 KiB 建立可复跑基线。可用应用接收 ACK 的往返 P99 ≤ 50 ms 作为初始预算假设，并记录处理失败、排队和存储模式。这个预算只覆盖接收回执，不包含技能执行完成时间。设定跨机目标前，先用相同负载单独量化网络、持久化和排队开销。

自测。看到 P99 上升而平均耗时变化小，如何从应用 ACK、发送队列和连接状态三组数据判断耗时在哪里。
