# M10 机器人实体构建 · 盘点、台架与增量扩展

P2 · S4/S5。你已具备小机器人软件基础，设备的型号、数量、环境和可用预算等实际条件进入选型前核实。

## 技术要求

- 设备建档。记录底盘、主控、连接方式、驱动/固件、传感器、动力和安全能力，注明兼容的 ROS、RMW 与驱动版本。
- 支持单机安全状态、传感器/执行器反馈、看门狗和恢复方式。可单独定位硬件故障、通信故障与应用故障。
- 给实体与模拟使用一致的设备接口、命名、版本和标定字段；每台设备都能独立标识并维护。
- 上电、空载、台架和低速都按厂商手册、现场安全规范和本地审批完成。

## 已有基础与待补能力

- **已有**。ROS 小机器人软件基础，已有工程构建与配置记录可借鉴。
- **待补**。可用设备清单、板卡/总线/驱动及支持约束、控制器配置、实机样例和维护记录。先查你的现有设备能否复用，再考虑新增实体。

## 学习内容与目标深度

| 学习项 | 达到的程度 |
|---|---|
| 设备选型读表 | D1。能读手册的接口、供电、额定范围、反馈、急停与固件支持，并填写复用判断 |
| 驱动与模型 | D2。能用官方界面/SDK核对状态，校验 URDF/SDF、传感器单位和 TF |
| 标定与维护 | D2。能记录参数、固件、误差及回退步骤，区分替换硬件和改地图造成的差异 |
| 多机归属 | D2。用 robot ID、固件指纹、配置和网络台账核对两个设备的角色 |

## 实施步骤

1. 先填写现有设备档案。列出机器人、主控、运行系统、SDK/驱动、反馈通道、传感器、急停和当前可复验证据。未知项标待查。
2. 选一个厂家明确支持的、风险可控的单机用途。按实体做对应的仿真模型，设定同样的单位与坐标系。
3. 逐级做静态识别、台架校验与低速任务；每一步留操作记录和状态。控制周期和物理边界沿用 M9/M12 的准入条件。
4. 复盘「1 实体 + 1 软件实例」的联合部署。统一任务接口和观测，标记实体与仿真的输出来源。
5. 用单机证据判断第二台物理设备的需要。对比现有复用、借用/实验室设备或后续新增时的接口、维护与费用，再安排第二台。

## 预期产出

一个按机器人编号归档的设备与配置档案、单机检查记录和可维护的 bringup 清单。若硬件条件待定，先以仿真交付，保留真实设备接入清单。

## 验收标准

| 检验 | 通过条件 |
|---|---|
| 可维护性 | 另一位同学能凭记录定位设备、固件、配置、复位和回退入口 |
| 单机闭环 | 通过安全准入后，通过受控场景完成任务、回报、停止和授权复位 |
| 配置隔离 | 设备 ID、TF、单位和传感器来源真实对应，多个节点的状态可在 Observer 区分 |
| 一致性 | 记录版本差异，标定、公差和仿真差异有可复核依据，布局和负载改变后重新核验 |

自测。设备重启后精度变差而软件版本相同，先检查哪三项近端可见状态与标定数据。
