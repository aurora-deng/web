# M4 C++ DAG 执行引擎 · 生命周期与调度

P0 · S1。五工序任务像一张有箭头的工单，没有完成前置工序的工位只能等，够条件时才可以占用有限的工位。

## 技术要求

- C++20 独立库和最小可运行示例，图定义、运行状态、技能调用和存储有清楚的所有权。
- 检测环、缺失依赖、重复节点；依赖满足后入就绪队列；并发、总期限与节点期限都有上限。
- 覆盖取消、重试、终态提交与资源回收。隔离模型、网络与数据库适配，运行时接受可控时钟和测试 worker。
- 为运维提供运行 ID、节点 ID、尝试编号、排队与执行耗时，关键节点可用同一 Trace 找到。

## 实施步骤

1. 先约定五节点图 `A → B/C → D → E`。B/C 可并发，D 汇合，E 回报。输出不可变运行定义，模型只能填经校验的参数。用一个小任务替身检查构图及终止。
2. 实现同步或单调度线程基线。依赖计数归零时入 ready，固定排序便于查错。工作线程只执行单元任务，完成后通知统一的状态持有者。
3. 引入有界任务队列、工作流总期限和节点期限。取消先停止派发，再向运行中的任务传递停止信号。不能立刻停止的调用继续占预算，迟到完成不能推进终态或下游。
4. 每次尝试分配独立序号。可逆/只读动作使用有界重试和退避，外部写操作按 Skill 合同持有同一命令 ID。任务结果不明时交给 M5 对账。先在同进程重放状态，再接持久存储和 Worker 租约。
5. 接入 M7 事件。报告排队、执行、重试、完成与取消确认；测固定图的 1、2、4 worker。只有数据说明需要时，再接协程适配或替换队列。

第一次投入 8 小时优先完成「三节点 + 可取消替身」。若卡在依赖或存储，先回到纯内存、单 worker 的 C++ 实现，用 Python 写参考断言。这样还能继续验证 C++ 生命周期。

## 预期产出

G1 交付五节点 C++ 程序、图和执行数据契约、状态测试、两张 Trace 以及同机器的调度基准。S1 的 32–46 小时包含技能/事件契约、引擎与验收。Fleet P0 复验了运行发现、续租和对账，后续用相同夹具增加真实业务容量测量。

## 验收标准

| 场景 | 断言 |
|---|---|
| 图校验 | 循环、重复节点和缺失依赖全部被拒绝；B/C 的完成顺序可变，D 只在两者均满足后执行 |
| 并发 | 至少 100 个固定种子运行；活跃 worker 从未超过配置，终态和 E 的结果各出现一次 |
| 取消/超时 | 分别在排队和执行时触发；下游保持未派发，超时后迟到结果不改变终态，退出后活跃任务归零 |
| 幂等/恢复 | 用合成写入验证重复尝试共用幂等键。崩溃后未知状态会出现可对账记录 |
| 性能 | 至少 3 轮同配置，带运行数、耗时 P50/P95/P99、最大队列深度和 RSS；记录最慢路径与采样误差 |

自测。超时发生在调用完成前一毫秒时，分别说清「调用还在执行」「任务已终止」和「谁会释放资源」。
