# M13 仿真、回放与 HIL · 验证阶段

P0 · S1/S2 做确定性软件夹具，P1 · S3 做 ROS 仿真，P2 · S4/S5 做台架。每次升级先写明被测试的环节和预期断言。

## 技术要求

| 阶段 | 接入对象 | 产出的证据 |
|---|---|---|
| 确定性模拟 | 协调器、边缘替身、可控钟和伪设备 | 图/重试/幂等/租约/拒绝的状态级证据 |
| SIL 与 ROS 仿真 | 真实任务与 ROS 软件加模拟底盘、反馈和环境 | 节点、Action、TF、QoS、时钟和多进程联调 |
| HIL | 实际控制器或目标计算硬件与模拟设备环境按待验证的 I/O 合同交互 | 真实接口、时序及异常响应。闭环 HIL 让控制器的输出改变模拟环境，模拟反馈随即影响下一周期 |
| 混合与现场 | 一个真实机器人和其余模拟实例，逐步进到真实多机 | 真实网络、设备和现场运维证据，标注各实例的来源 |

录包回放是可重复输入证据。只向硬件播放历史输入属于开环测量，控制输出是否参与后续反馈另行标注。

## 已有基础与待补能力

- **已有**。Observer 场景脚本能生成 DAG、失败、Agent 和设备合成事件，支持回读检查。现有故障复盘流程可作为报告模板。[场景脚本](../../../tools/observability/scenarios.py) · [历史故障验证](../../observability/validation.md)
- **待补**。固定行为断言的多机器人夹具、ROS 仿真版本、环境与回放包、台架设备和 HIL 闭环证据。优先沿用有效 ROS 环境。

## 学习内容与目标深度

| 学习项 | 达到的程度 |
|---|---|
| 种子、场景和断言 | D2。能用固定输入/地图/版本复跑，区分「启动成功」和「不变量成立」 |
| ROS 仿真 | D3。能调单机、两机、namespace、TF 和 QoS，解释一处仿真与实体差异 |
| 故障与回放 | D3。能轻量注入延迟、断链、重启和错误输入，报告观察窗口、断言及复现步骤 |
| HIL 准入 | D3。能画控制器、信号与模拟反馈的真伪边界，说明验证目标、停止路径、设备条件 |

可用仿真器优先满足现有 ROS 与驱动兼容。新建 Jazzy 环境时以官方 Gazebo 配套说明核对；依赖版本与资源单独记录。[Gazebo 与 ROS 配套](https://gazebosim.org/docs/harmonic/ros_installation/)

## 实施步骤

1. 单机同进程做图状态测试，再开两个独立边缘模拟进程。为每个场景编号、固定种子、超时和不可变预期记录。
2. 建首批 8 个场景。正常汇合、非兼容能力、迟到回调、ACK 丢失、协调器重启、网络分区、队列拥塞、时钟跳变。安全验证用受控的停机状态和授权夹具扩展。
3. 给一个模拟机器人接入真实 ROS Action 与虚拟底盘，录制并回放定位一次错误。加第二个仿真实例，检查配置、地图和资源。
4. 若现场具备设施，单独制定 HIL 配置和安全规程，用目标控制硬件连受控模拟接口，先验证输出不外接实际运动负载的场景。实体前完成 M9/M12 的准入。
5. 把报告写成机器和人都能复验的形式。保存版本、fixture 摘要、观察时长、断言、屏障/停止原因；按场景失败阶段快速回退。

## 预期产出

固定场景表、自动回归报告、一份 ROS 仿真回放、HIL 设计与条件清单。设备可用后添加真机/HIL 的实际结果；优先展示 G2 的软件回归和 G3 的仿真与观测证据。

## 验收标准

| 检验 | 通过条件 |
|---|---|
| 重复性 | 8 个首批场景各至少 3 次固定输入运行，记录成功/失败断言、时钟、时限与结束状态 |
| 软件与仿真 | 实体隔离时各自编排与停止正常。断线、重启和过期动作能从证据中查到，无重复的逻辑副作用 |
| 回放 | 对同一记录有版本、开始/结束时间和摘要，复验得到预期状态或明确等价误差 |
| HIL | 真实硬件、模拟部分、已核对的 I/O、控制周期和失效响应写入控制图，闭环反馈可测 |
| 晋级 | 仿真与台架各自门槛已通过并复核，现场出现异常按安全操作终止和归档 |

自测。两台软件机器人都按脚本同时到达目标，补哪三个观察量才能说明受控断网下的任务与停止仍然正确。
