# M9 执行器与实时控制 · 周期、抖动和失效

P2 · 实体准入。先把本地周期的计时和安全状态做成可重复测量的实验。执行器的额定范围和失效方式来自设备手册与现场验证。

2026-11-24 · C++ 控制周期、模拟执行器和 ROS 适配具备独立构建入口。CentOS 已记录三轮各 30 分钟，当前虚拟机空闲段 P99 唤醒迟到约 16 ms，100 Hz 时序门禁未通过。真实驱动与台架仍按 M10、M12、M13 验收。 [实测与复跑](../../ops/validation/m09-actuator-control.md) · [学习讲义](../../learning/m09-actuator-control.md)

## 技术要求

- 定义读、更新、写入的本地周期和数据龄期。记录计划唤醒、实际唤醒、执行完成、错过 deadline 与多周期抖动。
- 固定队列和资源，过期目标按本体策略丢弃或降级。控制路径与模型、日志、gRPC 回调以及阻塞 I/O 相隔离。
- 设备侧有看门狗、限速/限位、电源和急停约束。停止/复位定义与控制器、驱动支持相符。
- 先空载或闭环台架，使用厂商驱动或 `ros2_control` 已验证接口。实时 Linux 调整依赖测量和受控维护窗口。

## 已有基础与待补能力

- **已有**。你具备 ROS 应用基础，NEBULA 有排队、P99 和资源观察的经验。可迁移的是测量、并发及异常处理方法。
- **待补**。真实执行器协议、周期开销基线、控制失效反馈、本地安全操作与 RT 环境情况。硬件型号和台架条件待 M10 确认。[Controller Manager 文档](https://control.ros.org/jazzy/doc/ros2_control/controller_manager/doc/userdoc.html)

## 实施步骤

1. 先用模拟时钟与假执行器，定义本地控制周期、过期目标和异常反馈。以设备手册为后续实机阈值来源。
2. 在 Linux 非驱动程序测时，记录空载和同机受控负载分别如何影响周期。示例练习可用 100 Hz 假周期，具体实机频率以后单独确定。
3. 使用现成的硬件接口接入状态读数、控制更新与故障回报。引入有界交接，记录绝对周期偏差、回调执行耗时和丢弃。
4. 用控制器在环或无运动负载台架验证丢失反馈、过期目标与本地停机。按 M12/M13 准入完成低速实体验证。
5. 若测得抖动超出预算，先定位哪个部分超时，再比较调度/亲和/系统配置方案和代价。涉及内核、驱动或电源变更按独立实验审批。

## 预期产出

一张周期与数据流图、空载和干扰下的测量报告、设备安全态及复位证据。真实控制频率、阈值与测试时间根据实体和危害评估记录。

## 验收标准

| 检验 | 通过条件 |
|---|---|
| 周期统计 | 固定配置至少 3 轮，每轮 30 分钟模拟或受控台架测量，报告 P50/P95/P99、最大值、漏拍、负载和核配置 |
| 数据时效 | 输入工作在既定周期，过期状态按规则丢弃或降级，对应记录可追溯 |
| 安全链 | 台架注入失联、停更或驱动反馈异常，本地安全状态与阈值符合设备规程，且需授权复位 |
| 可复验 | 按操作说明能在相同配置得到相近的分布并指出影响因素，真实硬实时结论另行评估 |

自测。一轮实验的 P99 周期合格但出现一次很大的漏拍时，如何报告结果，请分别说控制指标和安全准入影响。
