# M3 模型训练与调度 · 数据、推理与部署

P2 · S5。模型工程优先服务于有明确定义的任务失败。前两个产出是可重放数据和可比较的规则基线。

## 技术要求

- 区分任务级 LLM 提案、低延迟能力推理、离线训练与回放评估。每类声明 deadline、资源、输入输出和装载版本。
- 数据集可追溯任务、设备、固件、时间与失败样本。训练集和评估集按采集会话/环境切割，记录数据授权及设备差异。
- 推理 worker 与业务调度隔离，入口有预算、队列和过载策略。模型产出经范围、新鲜度和安全约束检查，支持版本回退。
- 将文本提案与机器人策略的接口分别版本化。策略需要带时序的观测和动作，采取离线或受控仿真验证路径。

## 已有基础与待补能力

- **已有**。项目有 Ollama、ONNX 同进程与 gRPC Worker 接入，模型注册与故障降级，文本训练数据导出以及取消示例。[模型端口](../../../backend/ai/models/ModelProvider/ModelProvider.h) · [模型注册](../../../backend/ai/models/ModelRegistryService/ModelRegistryService.cpp) · [文本数据导出](../../../backend/ai/training/JsonlTrainingDataExporter/JsonlTrainingDataExporter.cpp)
- **待补**。绑定机器人任务的 episode 记录、多模态时间对齐、按负载类别隔离的调度，以及能复验的策略训练和部署报告。硬件、GPU、采集权限和模型许可在接入前盘点。

## 学习内容与目标深度

| 学习项 | 达到的程度 |
|---|---|
| PyTorch 与数据 | D2。能解释 batch、训练/验证划分、过拟合、固定种子，独立导出一个隔离的学习样本 |
| 机器人 episode | D2。能把图像/状态/动作与任务事件对齐、回放，标记缺帧、校准变更和可用区间 |
| 端侧推理 | D2。稳定运行一种已有 runtime，比较模型大小/内存/实际延迟；量化后重跑同一评估 |
| 资源调度 | D2。写出队列、超时、优先级和回退规则，证明模型负载不会占满工单接收预算 |

后续可选 LeRobot 的 ACT 作为小型策略离线练习，比较固定规则与学习输出，带输入、版本和评估口径。[LeRobot ACT](https://huggingface.co/docs/lerobot/en/act)

## 实施步骤

1. 记录固定任务的成功与失败 episode，写清 schema、观测和动作单位、数据许可、时间质量及回放范围。
2. 先用确定性提案或控制替身获得基线，分别记录任务完成率、安全拒绝、推理延迟和资源视图。
3. 把整段 episode 分区训练与评估，固定版本、采样配置和失效样本。选一个有稳定评估收益的最小模型，再考虑转换或加速。
4. 在独立进程接推理，并给任务提案、策略测试和离线评估设置不同容量。过载时优先保留控制面心跳和安全回报。
5. 完成离线、SIL 再到评审通过的 HIL 阶段。比较新旧模型及无模型模式，回滚到同样输入仍能复跑。

## 预期产出

一个小规模可回放的策略数据包或明确的数据缺口报告，一张模型卡、一组公平的基线与实验结果、资源与回退演练记录。S5 可先做纯 CPU 的数据、接口与模型离线评估，按已批准的设备扩展。

## 验收标准

| 维度 | 通过条件 |
|---|---|
| 数据 | 样本 ID 能对应任务与版本；训练、验证按会话分离，时间质量低的样本按规则隔离 |
| 评估 | 固定任务与种子，至少三轮；保留任务成功率、动作安全拒绝、P95/P99 和 RSS 或显存 |
| 调度 | 并发推理、超时和队列满时，控制消息仍按既定预算处理；可对照空载数据 |
| 回滚 | 以已验证版本回放相同夹具，结果可见且模型切换有审计 |
| 实体 | 输出陈旧、超范围、模型停止时本地安全态得到验证，真机准入见 M12/M13 |

自测。成功率提高而执行尾延迟变长时，怎样判断它适合后台提案、适合某类推理，或该先完成优化。
