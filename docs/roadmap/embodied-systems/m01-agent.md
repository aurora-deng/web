# M1 Agent 研发 · 母子职责、工具与评估

P1 · S4，S1 先参与定义接口。把 AI Native 的作品定义为「运行时有能力调用、权限、状态和评估」，首版让母 Agent 在车队证据之上给出可解释提案。

**当前已到 ROS 2 交接边界**。C++ 母 Agent 从车队证据创建模拟重排草稿，审批后由协调器原子入队，确定性边缘执行器收到并进入导航端口。Ollama 适配已用本机 HTTP 夹具验证，真实模型的提案质量单独取样。 [运行、代码导读与习题](../../learning/nebula-fleet-agent-and-skills.md) · [LangGraph 学习](../../learning/langgraph-nebula-lab.md) · [Skill 合同](skills/README.md)

## 技术要求

- 母 Agent 读取任务、失败摘要和能力目录，输出受限的结构化提案。提案携带证据引用、任务模板、参数和候选原因。
- 子 Agent 保存本体任务上下文，按明确的状态和技能合同执行。优先尝试确定性状态机或行为树，按需在非实时路径做有限的意图分类。
- 明确会话范围、读写权限、当前计划、取消和超时；工具调用有次数、延迟和内存预算。向用户和日志输出步骤状态与异常分类。
- 计划建议、审批和实际派发由不同权限边界控制。模型输出参与填参和建议，图定义和安全边界由已登记模板校验。

## 学习内容与目标深度

| 学习项 | 具体掌握程度 |
|---|---|
| 工具调用与数据流 | D2。画「观测 → 计划 → 校验 → 审批 → 回报」，写出模型输出的 schema、示例和错误处理 |
| 记忆与上下文 | D3。区分单次工单、短期历史、长期聚合证据和隐私数据。能说明权限变化时清理或重查哪个引用 |
| AI 失效与评估 | D3。独立测提案成功率、格式错误、权限拒绝、P95 延迟和成本；能在模型离线时定位降级分支 |
| 主控层次 | D3。解释任务可分派的条件、子系统什么时候接管、停止和人工复核事件由谁发出 |

母 Agent 像带证据的值班复盘员。给它同一份任务失败摘要，先检查结论能否追到原始事件，再允许它提出下一步。

## 实施步骤

1. 用假 provider 做两种固定提案，例如「重新安排未发出的模拟工单」和「概括最近三次失败」。输出必须匹配固定 schema 与已允许的模板。
2. 以 M2 的技能 ID 和版本写工具白名单。先接状态查询和任务建议两个工具，所有口令、参数和权限在模型之外验证。
3. 将流程接到 C++ runtime 和 M5。操作者确认后生成独立工单 ID，调度器用本体实时状态重新判定。拒绝和降级要能从 Observer 看见。
4. 接已有模型端口，设置输入上限、调用 deadline、并发和调用次数。断网或模型质量不足时回到固定工单/规则；无有效提案时给出证据摘要。
5. 固定评测集，对比「规则基线」与「模型辅助」。拆分两类失败，选择已审核摘要供下轮改技能或数据；运行数据按权限留存。

## 预期产出

20–30 小时先交付只读总结与提案原型、提案审批演示、评测集与回放结果。D3 达成后再扩展更多正式 Skill 和长期记忆。

## 验收标准

| 场景 | 断言 |
|---|---|
| 正常与缺失输入 | 至少 20 条固定离线样本，报告合法提案和可解释拒绝比例，提案引用能查到 |
| 异常输出 | 未登记能力、超预算和不符 schema 的输入全部拒绝，调度账本新增动作数为零 |
| 取消与模型离线 | 模型占用释放或保留到实际结束，固定工单路径有确定结果 |
| 审批与状态权威 | 同一提案重复确认只产生一个工单。批准后若租约或安全前置变化，派发有可见拒绝 |
| 现场可核对 | 每次提案、工具尝试、审批和拒绝均可按一次运行查询，敏感输入按策略脱敏 |

自测。母 Agent 说「A 最近一直慢」，你能如何用同一时间窗、失败分类和对照机判定这个解释。
