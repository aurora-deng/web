# M11 时间同步与一致性 · 时效、顺序与归因

P0 · S1 定时间语义，P1 实测跨主机。时钟像两台各自走的秒表，比较绝对读数之前要知道它们的出发点和误差。

## 技术要求

- 本机 deadline、排队和租约检查使用单调时钟。跨机记录使用可说明误差的同步时间。仿真/回放用 ROS Time 并处理暂停、跳变和重置。
- 标识独立于时间。事件至少带 `robotId/bootId/sessionId/streamId/sequence`，关联 `commandId` 与 `fenceEpoch` 由合同决定。
- 记录来源与接收时间、时间质量、测量方法及误差区间。跨时域不可比时保留「未知」，分析 ACK 往返使用同一主机的单调钟。
- 使用有界重排序窗口，区分延迟、重复、漏帧和进程重启。涉及物理动作的时效不能证明时按本地安全策略处理。

## 已有基础与待补能力

- **已有**。Observer 的设备窗口和命令事件已包含序列、缺帧、迟到、偏差质量等字段。合成场景已有重排参考。[设备事件](../../../tools/observability/observer/events.py) · [样例](../../../tools/observability/scenarios.py)
- **待补**。机器人进程的时钟接口、会话切换和跨机误差测量。来源到接收的时间差同时混有时钟偏差、链路延迟和排队，需要单独校正。

## 实施步骤

1. 给 DAG 和边缘状态机注入可控单调时钟，明确定时器和时间戳字段属于哪个时域。
2. 给每次设备启动、连接和数据流分别发 ID，模拟丢帧、序号跳变与重启。对时钟质量定 `synchronized/unsynchronized/unknown` 等状态。
3. 在模拟和受控两主机条件下做往返时序测量，附时间同步配置、采样窗口、网络非对称假设和误差估计。同期用 ACK RTT 验证。时钟质量不足时隐藏单程分位。
4. 为本地接收定义有限重排窗口。重复报文查账本，超出窗口的迟到数据进入统计，旧会话事件不能更新新会话状态。
5. 验证租约与时效。固定一个工单的最近状态、认证会话和期限，回放延迟报文及墙钟变化，不让旧角色重新获得权限。

## 预期产出

一份时间字段矩阵、一套序列水位夹具、一张跨机测量或环境阻塞记录。G2 达成 D2，跨两台真实主机给出误差口径后达 D3。

## 验收标准

| 场景 | 通过条件 |
|---|---|
| 墙钟跳变 | 人为注入测试钟跳变，单调 deadline 与本机 ACK RTT 不倒退 |
| 重启和重排 | 固定包含重复、迟到、缺口和重启的样本，逐类计数正确，旧会话状态不写入新会话 |
| 分区 | 过期命令按策略拒绝，恢复需当前会话与有效租约；可逐条读回证据 |
| 跨主机 | 报告两机环境、采样和误差区间，误差超过项目所设的测量预算时放弃单程判定 |

自测。同一条消息的墙钟显示负延迟，如何区分调度顺序、系统时间偏置和真实链路等待。
