# M12 安全架构 · 任务授予、本体仲裁和应急证据

P0 · S1 定最小安全约束，P1 · 真机准入。把云端任务授权、边缘执行准入和设备保护分成三处决策。

## 技术要求

| 层 | 拥有的权限 | 失败时的行为 |
|---|---|---|
| 车队服务 | 核对操作者、机器人身份、任务模板、能力、分区权限和租约 | 拒绝非法或失效的计划与派发，留下脱敏理由 |
| 本体任务层 | 核对当前会话、命令时效、预置目标、资源和已允许动作；本地复核每个动作 | 执行条件不足时切到本地保持或安全态，保留重连对账 |
| 控制器和设备层 | 执行设备的限速/限位、看门狗与急停，本地操作者能发现和复位 | 现场保护独立工作，复位按设备规程和权限处理 |

每台机器有独立设备身份及撤销办法。跨主机控制使用可信连接与身份绑定。敏感元数据最小化，日志有访问、保留和轮换规则。把物理风险、拒绝理由和安全状态显式建模。

## 已有基础与待补能力

- **已有**。独立车队按机器人令牌和站点白名单派发，跨机链路通过校验主机公钥的 SSH 转发。旧会话与错误占有代号无法推进任务，重启可查到待对账结果。 [跨机与故障验收](../../ops/validation/cpp-systems-cross-vm.md)
- **待补**。现场身份签发、控制权移交、准入、紧急停止和复位记录。不同设备的保护能力要结合手册和场地确定。

## 学习内容与目标深度

| 学习项 | 达到的程度 |
|---|---|
| 威胁建模 | D2。画站点、服务、机器人和控制器信任边界，列出每处需要保护的状态 |
| 身份与权限 | D3。能用设备标识绑定 TLS 身份，限制允许的目标/功能，演练离线设备撤销与重连 |
| 安全状态机 | D3。给出就绪、有限执行、保持、停机和本地复位条件。能解释哪个组件发出事件与哪个执行停止 |
| 验证与审计 | D3。能为每项安全属性写一条场景与证据，区分模拟、台架和有资格条件下的实体结论 |

## 实施步骤

1. 写一张「动作 → 资格 → 允许范围 → 停止/复位 → 证据」矩阵。把只读状态、模拟可逆任务和会产生物理动作的任务区分开。
2. 在协调器验证身份、权限、代号和时效。本体再核对当前技能、最近状态和资源。对过期命令、额外字段或越界输入给出有分类的拒绝。
3. 把控制器自有的保护及设备状态纳入 M9 的台架验证。以监护人员、区域隔离、停止路径、设备速率/负载约束和回退方式确定上机准入。
4. 先在合成和仿真输入上验证拒绝策略。新策略在仿真或不接执行器的回放中做影子验证，批准后再进入有物理输出的流程。
5. 演练断网、重启、权限撤销和时钟不可信。状态变更上报到 Observer，稳定结果由本体的有效状态和 M5 对账确认。

## 预期产出

系统威胁与风险清单、最小动作白名单、身份与撤销流程、应急和测试矩阵。一条从拒绝命令到安全状态的可复查证据。

## 验收标准

| 场景 | 通过条件 |
|---|---|
| 身份、权限与时效 | 未登记设备、旧代号、过期命令和越界输入在执行前返回预定拒绝，任务副作用为零 |
| 模型异常 | 在仿真注入格式和权限错误，Agent 提案直接进入拒绝路径，人工审批和本地准入各自有效 |
| 断连与安全态 | 本体能独立停止或进入批准的安全态，现场恢复按设备要求进行。重连只在状态明确后继续 |
| 初次实机 | 有场地和安全复核记录，设备保护与本地停止经台架验证，初次低速实验有可见停止与回报 |
| 证据 | Trace/Command ID、拒绝类型、设备和必要时间可定位，凭据和原始私密输入按权限处置 |

自测。云端重新分配新任务时，机器人仍处于现场复位流程。列出三层各自能读、能批和能动的东西。
